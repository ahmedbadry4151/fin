## الملخص التنفيذي

| F-02 | إدخال رقمي غير مقيَّد يصل إلى محرك مونت كارلو → استنفاد الذاكرة / تعطل | **متوسطة** | مؤكدة |

## F-01 — إجراءات الخادم غير المصادَّقة والقابلة للاستدعاء عبر الشبكة (مرتفعة)

**الموقع:** `src/lib/server-api.ts:1` (الملف بالكامل)، `src/lib/data.ts:20-29`، `src/lib/store.ts:221-227`.

يحمل `server-api.ts` توجيه `"use server"` واحداً في السطر 1. وبموجب Next.js، تصبح كل دالة `async` مُصدَّرة في هذه الوحدة نقطة نهاية `Server Action` قابلة للاستدعاء علناً عبر POST. **لا يوجد أي فحص لجلسة أو ملف تعريف ارتباط أو رمز أو دور أو CSRF في أي منها.** دالة الهوية الوحيدة هي:

```ts
// src/lib/data.ts:25-29
export async function getCurrentUser(): Promise<User> {
  await touchDynamic();          // يستورد next/headers cookies() فقط لفرض العرض الديناميكي
  const s = getStore();
  return s.users[0];             // دائماً المستخدم الثابت نفسه
}
```

تستدعي `touchDynamic()` (`data.ts:20-23`) الدالة `cookies()` فقط للخروج من العرض الثابت — ولا تقرأ أبداً جلسة. وبالتالي يمكن لأي مستدٍ عبر الشبكة استدعاء إجراءات تُدمّر الحالة دون أي بيانات اعتماد:

- `dataDelete("profile")` (`server-api.ts:605-638`) يمحو المعاملات والحسابات والأصول والالتزامات والأهداف والسيناريوهات والمحاكاات والتقارير ورسائل الذكاء الاصطناعي والإشعارات، ويعيد ضبط الملف المالي.
- `onboardingPost(...)` (`server-api.ts:482-581`) يستبدل المستخدم ويحذف/يعيد إنشاء كل الحسابات والأصول والالتزامات والأهداف.
- `dataExport()` (`server-api.ts:585-603`) يُعيد مجموعة بيانات التوأم بالكامل.
- كل إجراءات CRUD (`accountsOp`, `assetsOp`, `liabilitiesOp`, `transactionsOp`, `goalsOp`, `scenariosOp`, `simulationsOp`, `reportsOp`, `notificationsOp`) تعدّل المخزن المشترك.

عمليات الفحص `a.userId === user.id` المنتشرة في الملف (مثل الأسطر 118, 130, 149, 159, 187, 200, 247, 288, 302, 316, 339, 350, 384, 404, 450, 457, 469) **ليست تحققاً من الصلاحية** — فـ `user.id` هو دائماً `s.users[0].id`. لا يوجد حقل دور (role) للمستخدمين في أي مكان (`src/lib/types.ts:7-22`).

**حدود الثقة / الأثر:** يمكن لطرف أقل ثقة عبر الشبكة تنفيذ كل تغييرات الحالة ذات الامتياز وقراءة كل البيانات. كما يتشارك جميع الزوار مخزناً singleton واحداً على مستوى الوحدة (`store.ts:221-227`) وعلماً globals واحداً `pendingSignup` (`server-api.ts:34`). في التطبيق التوضيحي المُسلَّم هذا مقصود (`README.md:66-67`، بيانات توضيحية في الذاكرة تُعاد عند إعادة التشغيل)، لذا فإن الأثر العملي مقتصر على بيانات العرض. **أما إذا نُشرت هذه الشفرة ببيانات مستخدمين حقيقيين أو خلف تسجيل دخول حقيقي، فهي استيلاء على الحسابات والوصول إلى بيانات عبر المستأجرين دون أي مصادقة.**

**الإصلاح:** عامل كل دالة مُصدَّرة كنقطة نهاية غير موثوقة. تحقق من جلسة/رمز حقيقي في بداية كل إجراء، واجعل كل عملية قراءة/كتابة مقيدة بمعرّف المستخدم المصادَّق عليه (وليس `users[0]`). وإذا كان المشروع سيبقى توضيحياً، فقيّد نشره بحيث لا يُكشف أبداً مع بيانات حقيقية، وصرّح بذلك بوضوح في ملف README.

## F-02 — إدخال رقمي غير مقيَّد يصل إلى محرك مونت كارلو (متوسطة)

**الموقع:** `src/lib/data.ts:248-252`، `src/lib/server-api.ts:359-374, 466-473`، `src/lib/simulation.ts:185-189`، `src/lib/economy.ts:85-97`.

تقيّد `runAndStoreSimulation()` قيمة `paths` إلى `[100, 5000]` في `data.ts:250`، لكنها **لا تقيّد `horizonYears`**:

```ts
// src/lib/data.ts:248-252
const econ = { ...twin.econ, ...(opts.assumptionsOverride ?? {}),
               horizonYears: opts.horizonYears ?? twin.econ.horizonYears };
const paths = Math.min(5000, Math.max(100, opts.paths ?? 600));
const results = runSimulation(simTwin, econ, params, { paths, seed, ... });
```

نقطة الدخول العلويتان تقبلان أرقاماً عشوائية عبر `Number()` دون فحص للانتهائية أو النطاق — `simulationsOp` في `server-api.ts:369-372` و`assumptionsPatch` في `server-api.ts:471-472` (`Math.round(Number(...))`). النطاق الصالح الموثَّق هو `1..30` (`economy.ts:85-97`) لكنه لا يُفرَض أبداً على الخادم. كما أن `assumptionsOverride` / `paramsOverride` مجرد تحويلات TypeScript عبر `as` (`server-api.ts:371-372`, `data.ts:248-249`) دون أي تحقق وقت التشغيل من الشكل.

المصبّ في المحرك:

```ts
// src/lib/simulation.ts:186-189
const months = Math.max(12, Math.round(a.horizonYears * 12));
const nw: Float64Array[] = Array.from({ length: months + 1 }, () => new Float64Array(paths));
```

قيمة `horizonYears` كبيرة منتهية (مثل `1e7` → `1.2e8` شهر × 5000 مسار × 8 بايت) تُنتج تخصيصاً هائلاً؛ و`Infinity` أو `NaN` أو أسّ ضخم من سلسلة مثل `"1e309"` يجعل `Array.from({ length: Infinity })` يرمي `RangeError`. نفس فئة الأرقام غير المُتحقَّق منها تغذّي `savingsChangePct` و`incomeDurationMonths` وغيرها من محلّلات اللغة الطبيعية (`src/lib/intelligence.ts:119-121, 152-157`, `src/lib/scenarios.ts:299-388`)، وتنتقل قيم الفيضان / `Infinity` عبر `finance.ts` و`store.ts` (مثل `Math.abs(Number(t.amount) || 0)` في `server-api.ts:231` الذي يسمح لـ `Infinity` بتعيين `acc.balance = Infinity` في `server-api.ts:216`).

**حدود الثقة / الأثر:** يمكن لأي مستدٍ لإجراء المحاكاة (غير المصادَّق عليه بحسب F-01) إجبار الخادم على تخصيص ذاكرة مفرطة أو استثناء غير مُعالَج في العملية المشتركة — عيب توفر محلي محدود. وبما أن المخزن مشترك، فإن تعطل مستدٍ واحد أو تجاوزه يؤثر على جميع الزوار.

**الإصلاح:** تحقق من كل مدخلات الأرقام في إجراءات الخادم باستخدام `Number.isFinite` وفرض الحدود من `ASSUMPTION_DEFS` (`economy.ts:19-98`) عند حد الثقة: قيّد `horizonYears` إلى `[1, 30]` (و`paths` مقبّد بالفعل)، وارفض `NaN`/`Infinity` قبل أي تخصيص. أضف اختبار انحدار للقيم `Infinity` و`1e9` والقيم السالبة لـ `horizonYears`.

## F-03 — تصدير CSV / Excel: اقتباس معطوب وحقن صيغ في جداول البيانات (متوسطة)

**الموقع:** `src/lib/server-api.ts:411-439` (بناء الصفوف في 416-428)، `src/lib/client-api.ts:103-114, 124-128`.

يبني `reportsExport()` نص CSV باستخدام قوالب السلاسل و`JSON.stringify()`:

```ts
// src/lib/server-api.ts:423, 427
...twin.goals.map((g) => `goal,${JSON.stringify(g.name)},${g.currentAmount}/${g.targetAmount}`),
...tx.map((t) => `${t.date},${JSON.stringify(t.description)},${t.category},${t.type},${t.amount}`),
```

تضع `JSON.stringify()` السلسلة بين علامتي تنصيص لكنها **لا تُكرِّر علامات التنصيص الداخلية**، ولا تهرب الفواصل أو الأسطر الجديدة في الحقول الأخرى. والأهم أنها **لا تُحيِّد بداية `=` أو `+` أو `-` أو `@`**. أسماء الأهداف (`goalsOp`، `server-api.ts:273`) وأوصاف المعاملات (`transactionsOp`، `server-api.ts:228`) خاضعة بالكامل للمستخدم. وصف مثل `=HYPERLINK(...)` أو `=DDE(...)` يُكتب كـ `"=..."`؛ وتطبيقات جداول البيانات تُزيل علامات تنصيص CSV وتقيّم الخلية كصيغة عندما يفتح الضحية الملف المُنزَّل. ثم تُمرّر `exportReport()` (`client-api.ts:124-128`) هذا المحتوى إلى `triggerDownload()` مع MIME من نوع `application/vnd.ms-excel` / `text/csv`.

**حدود الثقة / الأثر:** يُخرج المُصدِّر نصاً خاضعاً للمهاجم في ملف يستهلكه سياق أعلى امتيازاً (تطبيق جداول البيانات لدى المشغّل). هذا هو حقن الصيغ الكلاسيكي في CSV: تسريب بيانات أو تنفيذ أوامر على الجهاز الذي يفتح التقرير. كما يُنتج CSV مشوّهاً للأوصاف العادية التي تحتوي علامات تنصيص أو فواصل.

**الإصلاح:** نفّذ تهريباً حقيقياً لـ CSV (كرِّر كل `"`، وضع بين علامتي تنصيص الحقول التي تحتوي `,` أو `"` أو `\n` أو `\r`) وأسبق أي خلية يبدأ حرفها الأول بـ `= + - @` (أو جدولة/CR) بعلامة تنصيص مفردة قبل الاقتباس. أضف اختبار وحدة بوصف مثل `=1+1` وآخر يحتوي علامات تنصيص وفواصل داخلية.

## F-04 — صفحة الأمان العامة تروّج لمزاعم حماية غير موجودة (متوسطة)

**الموقع:** `src/components/views/public-pages.tsx:87` (التزام "أمان الجلسة")، بالمقارنة مع `src/lib/server-api.ts:36-73`، `src/lib/data.ts:20-29`، `src/lib/store.ts:100`، `README.md:39, 66-67`.

تنص صفحة `/security` على ما يلي:

> "ملفات تعريف ارتباط جلسة موقّعة بـ HTTP-only ومدة 30 يوماً. كلمات المرور مُجزَّأة بخوارزمية scrypt."

لا شيء من هذا موجود في البناء الحالي. لا توجد ملفات تعريف ارتباط إطلاقاً (`data.ts:20-23` يستدعي `cookies()` فقط لفرض العرض الديناميكي)، ولا تجزئة كلمات مرور (حقل `passwordHash` للمستخدم الوحيد هو السلسلة الحرفية `"demo"` في `store.ts:100`، و`authPost("login")` / `authPost("demo")` تُعيد النجاح دائماً في `server-api.ts:46,48`)، ولا أي تنفيذ لـ scrypt أو جلسات (`README.md:39` يُدرج `src/lib/session.ts` ضمن الملفات المحذوفة).

**حدود الثقة / الأثر:** يُبلغ زائر يقيّم أداة **مالية** أن حماية قوية ومحددة تحمي بياناته بينما لا شيء من ذلك موجود. هذا تصريح أمني مضلل يمكن أن يدفع المستخدمين إلى إيداع بيانات مالية حقيقية لدى نظام لا يحميها — ضرر حقيقي يمكن للمالك ملاحظته، مستقل عن كون بيانات التطبيق التوضيحي synthetic.

**الإصلاح:** إما حذف العبارة أو إعادة صياغتها لوصف سلوك التوضيح الفعلي (لا مصادقة، بيانات في الذاكرة، ولا حفظ)، أو تنفيذ ضوابط الحماية المُدعاة. لا تُشحن وعود أمنية لا تفرضها الشفرة.

## F-05 — غياب ترويسات الأمان وCSP (منخفضة)

**الموقع:** `next.config.ts:1-5` (إعداد فارغ)، `src/app/layout.tsx:51-54`.

`next.config.ts` فارغ: لا `headers()`، ولا CSP، ولا `X-Content-Type-Options`، ولا `X-Frame-Options`/`frame-ancestors`، ولا `Referrer-Policy`، ولا `Permissions-Policy`، ولا HSTS، وإعداد `X-Powered-By` متروك للقيمة الافتراضية لذا تُكشف الترويسة `X-Powered-By: Next.js`. تحمّل الصفحة خطوط Google من `fonts.googleapis.com` / `fonts.gstatic.com` (`layout.tsx:51-53`) دون SRI، وتنفّذ سكربتاً مضمّناً عبر `dangerouslySetInnerHTML` (`layout.tsx:54`)، لذا فإن أي CSP صارم يحتاج حالياً إلى nonce/hash أو `'unsafe-inline'` لهذا السكربت.

**حدود الثقة / الأثر:** فجوة تصلب (hardening)؛ لا يُثبت استغلال منفرد، لكن النقر المُخفي (clickjacking)، وتخمين نوع MIME، ومصادر السكربتات/الأنماط الخارجية غير المقيدة كلها ممكنة. منخفضة الشدة لتطبيق توضيحي.

**الإصلاح:** أضف `poweredByHeader: false` ومقطع `async headers()` يضبط `Content-Security-Policy` (مع nonce لسكربت الثيم) و`X-Content-Type-Options: nosniff` و`X-Frame-Options: DENY` / `frame-ancestors 'none'` و`Referrer-Policy: strict-origin-when-cross-origin` و`Permissions-Policy`.

**الموقع:** `src/lib/constants.ts:1-2`، `src/lib/store.ts:100`، `src/components/views/auth.tsx:12, 101`، `README.md:24-29`.

الثوابت `DEMO_EMAIL = "demo@fintwin.app"` و`DEMO_PASSWORD = "fintwin123"` مكتوبة في المصدر ومُظهرة في صفحة الدخول. هذا مقصود لتطبيق توضيحي وموثّق في README. وهو في الغالب عديم الأثر: تسجيل الدخول يقبل أي بيانات اعتماد (`server-api.ts:46`)، فلا توجد كلمة مرور تُفحص فعلياً. لا توجد متغيرات `process.env` أو `NEXT_PUBLIC_*` أو مفاتيح API أو رموز في `src/`.

## تمت مراجعتها — لا توجد مشكلة

- **حقن DOM / تنفيذ سكربت:** المصبّ الوحيد للـ HTML الخام هو سكربت الثيم الثابت وقت التجميع في `src/app/layout.tsx:54`؛ ويُتحقق من لون `localStorage` بالتعبير `/^[0-9a-fA-F]{6}$/` (`layout.tsx:27`) قبل `setProperty`. لا يوجد `eval` أو `new Function` أو `.innerHTML` أو `outerHTML` أو `insertAdjacentHTML` في أي مكان ضمن `src/`. النصوص الخاضعة للمستخدم المعروضة عبر React (إجابات الذكاء الاصطناعي، أسماء التقارير، أوصاف CSV) تُهرَّب تلقائياً.
- **إعادة توجيه مفتوحة:** كل أهداف التنقل ثوابت يحددها الخادم أو معرّفات رقمية؛ وروابط استعلام المعاملات مُشفَّرة بـ `encodeURIComponent` (`server-api.ts:661`)؛ ولا يوجد `window.location` أو `window.open` أو `document.write` أو معامل `redirect`/`next`/`return` غير مُتحقَّق منه يتدفق إلى التنقل.
- **SSRF / اجتياز المسار / حقن SQL:** لا يوجد عميل HTTP على الخادم، ولا بناء مسارات ملفات من إدخال المستخدم، ولا طبقة قاعدة بيانات في هذا البناء.
- **تلويث النموذج الأولي (prototype pollution):** `profilePatch` يفرد `b.settings` (`server-api.ts:83`) في كائن عادي؛ ولم يُعثر على معالجة لمفاتيح تكتب إلى `__proto__` في مصبّات.
- **CSRF:** لا توجد ملفات تعريف ارتباط أو جلسات في التوضيح، لذا فإن تغييرات الحالة عبر مواقع متبادلة ممكنة لكنها تؤثر فقط على حالة التوضيح المشتركة؛ وهذا مشمول بإصلاح F-01.
